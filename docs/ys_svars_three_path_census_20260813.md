## 0. 判定强度（先读这一节）

上一版的错误不是「58 个调用点解错了」，是把「包装器路径的全集」写成了「插件读 S 的全集」。两条缺口叠加之后，**表里没有 ≠ 没人读**。

| 强度 | 含义 | 本轮哪些结论属于这一档 |
|---|---|---|
| **全集（该路径）** | 该路径上每一个调用点都扫到了，坐标/裸偏移列表对该路径是封闭的 | 路径 1 的 `0x10056040` 58 个 `E8` 调用点；路径 2 的 101 个 builder 站点里 **93 个已解码模板** |
| **至少包含** | 正面命中可以引用；未出现不能当「不存在」 | 路径 2 的 8 个未恢复模板；插件 `.text` 直读；路径 3 虚拟化函数内部 |
| **不能当否定式** | 禁止「表里没有 → 删除 / INVENTED / 没人读」 | 一切基于旧 5.1.0.5 表做的归属结案（`S(1,1)` / `S(1,2)` / `S(1,125)` / `S(1,205)` 等） |

`player+0x804` 是引擎 S 银行指针，三处独立字节：

```
0x6DF1CF  8B 93 04 08 00 00     mov edx, dword ptr [ebx + 0x804]   ; GetS
0x6DF26D  8D 93 04 08 00 00     lea edx, [ebx + 0x804]             ; SetS
0x6E42CC  69 C2 E8 03 00 00     imul eax, edx, 0x3E8               ; key = group*1000+index
0x6E42D2  03 C1                 add eax, ecx
0x6E42D4  C3                    ret
```

扁平键公式只在「指令把某个立即数拿去和银行字段比较，且该立即数满足 `group>=1 && 1<=index<=999`」时用来**命名**坐标。`0x522`（1314）是初始化标记值，不是 `S(1,314)`。`0x3E8`（1000）在切割路径里是千分比阈值，不是 `S(1,0)`。

## 3. 路径 3：Themida 逐函数虚拟化（判定边界）

形状：`push <.rdata>` / `jmp` 进 VA `0x10400000..0x11400000`（文件偏移 `0x400000..0x1400000`）。该 16 MB 在本转储 **100% 全零**（`gap_zero_ratio = 1.0`）。

| 项 | 数 |
|---|---|
| 满足上述形状的入口 | **275** |
| 涉及不同函数（`CC CC` 边界） | **255** |

S 相关的已知入口——SetS detour 本体：

```
0x100CEB40  55                     push ebp
0x100CEB41  8B EC                  mov ebp, esp
0x100CEB43  53 56 57               push ebx/esi/edi
0x100CEB46  90                     nop
0x100CEB47  68 70 6C 2C 10         push 0x102C6C70
0x100CEB4C  E9 81 11 B9 00         jmp 0x10C5FCD2     ; 落在零页
```

安装点仍在原生码：`0x100CEC39 push 0x100CEB40 / push 0x6DF246 / push 0x6DF240`（见 5.1.0.2）。**`S(1,1)` 禁言 7/8 的语义在这个零页里**，本转储永久不可判，除非重抓含 VM 段的 dump。

255 个虚拟化函数内部若再读 S，路径 1/2 **都看不见**。路径 3 对坐标表的贡献是边界声明，不是坐标列表。

## 5. C# 对账

脚本 API 本身（`GetS`/`SetS` 原语）与引擎契约对齐：miss = `-1`，`group>0 && index>0`，扁平键 `group*1000+index`。见 `PasApiBridge.cs` `GetPlayerVar` / `NativeScriptVarArgsAccepted`，`TPlayObject.Base.cs:264` `TryGetScriptVar`。

**插件消费层几乎是空的。** `GameSvr` 里 `TryGetScriptVar('S'` **零命中**。除脚本原语和商城 `S(80,40)` / `S(300,*)` / `S(301,*)`（与眼神坐标无关）外，唯一点名眼神坐标的活代码是：

```478:479:GameSvr/ScriptSystem/PasEngine/PasApiBridge.Yanshen.cs
            api.VacuumMonstersEx(GetPlayerVar('S', 1, 123).AsInt(),
                GetPlayerVar('S', 1, 124).AsInt(), 0);
```

`S(1,123)` / `S(1,124)` **不在** 路径 1 常量集、也不在路径 2 已命名 key 集。可能在 VM / 未恢复模板 / 文档。**不许**判 INVENTED，也 **不许** 当成已证实的原生读。强度：C# 有消费者，原生三条路径未见 → `BLOCKED`（缺：那两个坐标的字节读点）。

| 判定 | 内容 |
|---|---|
| `FAITHFUL` | 脚本 `GetS`/`SetS` miss=-1、拒绝非正参数、扁平键 |
| `MISSING` | 路径 1/2 已证实的全部插件消费（切割 `S(1,9..11,50..53,62,63)`、永久属性 `S(1,13..23,31..41)`、技能变址 `S(7/8/9,magicid)`、§4.1 其余 R 行）。C# 战斗/属性代码不读这些槽；`YanshenApi.CustomDamage` 只用传入的 `cuttingV`，不读 S |

## 6. BLOCKED

1. **银行对象布局**（`sub_6E4270` 的 key 合成与条目排布）未入库。`bank+0x1E4` 等不能换成 `S(g,i)`。卡在布局代理。
2. **8 个 trampoline 模板未恢复**，其中 `0x100D120A` 永久属性第一站很可能含 `S(1,12)`/`S(1,30)`。卡在 `rep movsd` / `movaps` 回放对该站点失败。
3. **255 个 Themida 虚拟化函数**（含 SetS detour `0x100CEB40`）跳进全零的 16 MB。卡在转储没带 VM 段。`S(1,1)` 禁言语义在这里。
4. **插件 `.text` 直读未穷尽编码**。只扫了 `ModRM+disp32 04 08 00 00` 的 `mov`。SIB / 8 位位移 / 拆开的立即数会漏。
5. **C# `S(1,123)`/`S(1,124)`** 吸怪参数：三条路径未见对应读点，文档有。缺原生 VA。
