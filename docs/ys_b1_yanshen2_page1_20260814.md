### 2.3 消费者普查：布尔开关的 `0x1F4` 判据

加载器把布尔开关编码成 `rand()%1000+1000`（开）/ 小模数（关），
所以**任何**消费者都长这一条指令：

```
cmp dword [reg + OFF], 0x1F4
```

按字节模式全库搜索这条指令，**不依赖基址寄存器的来源**。这一点是关键：
我先写了一版沿 `mov reg,[0x1031C0E0]` 向前跟踪指针的普查，
拿对照组一量**全军覆没**（`装备吸血`/`中毒时间上限`/`屏蔽排行榜` 一个都找不到），
因为 apply 臂是把配置对象当 `this` 收进来的，函数里根本没有那条 load。
换成字节模式之后对照组全部命中，方法才可信。

两份转储都扫。**只有 delayed 那份含 `0x10400000..0x11400000` 这 16 MB Themida 远端区**
（实测：转储 A 该区 `0/16777216` 字节非零，转储 B `16506511/16777216` 非零），
所以"无消费者"这种否定结论只在转储 B 上才成立 —— 本文所有否定结论都基于转储 B。

2. **看似命中的 `cmp [reg+OFF],0` 全是别的对象。** 例如

3. **`技能触发脚本` 特别核过。** 它的 `+0x508` 在 `0x100D269F` 出现，但同样落在

   `0x766624`＝`被击杀触发`。真正的 `技能触发脚本` 字段无人读。

**⇒ C# 现状（访问器存在、无人调用）与原版行为完全一致。这 20 条应当从 `MISSING`

#### 3.2.5 为什么这 9 条一律 fail-closed

**`sub_100795C0` 在两份转储里 0 个静态引用。** 逐项排查：

| 探针 | 结果 |
|---|---|
| rel32 `E8/E9` 调用（全文件，两份转储） | 唯一 1 处：`0x10F2D759 call 0x100795C0` |
| 该调用点所在区域 | `0x10400000..0x11400000`，**Themida 远端区**，指令流是重度 mutation（垃圾标志运算、假跳、`jmp 0x11448489` 链） |
| 绝对 dword 引用（全文件） | 0（只有函数内部的跳转表） |
| `.rdata` trampoline 模板里指向插件 `.text` 的 `E8/E9` 元素 | 全库仅 7 处，目标是 `0x1025414E/0x1025415C/0x1025505E/0x1025506C/0x1027224D/0x10272258`，**没有一处指向这条流水线** |

⇒ 这条流水线挂在宿主的哪个点上，静态**不可证**。C# 侧的伤害管线形状与原生不一定
一一对应，在没有挂载点的情况下选一个位置插进去，就是发明一个时机 ——
与 `ys_aclass` §5.3（噬魂沼泽绿毒"管线形状不同，不接"）同一条纪律。
**9 条全部 fail-closed。**

**解锁这 9 条只差一件事**：把 `0x10F2D759` 所在函数的宿主入口找出来。可行路径有两条 ——
(a) 对 Themida 远端区做去混淆 / 反虚拟化，把 `0x10F2D759` 的调用链上溯到某个 trampoline；
(b) 活体调试：在 `0x100795C0` 下断点，读返回地址链。任一成功，五条切割键 +
`英雄千分比免伤` 立刻可落（语义已经逐字节备齐，见 §3.2.1/§3.2.2）。
