## 1. 机制：眼神怎么改 M2Server

### 1.1 三种改写方式并存

| # | 机制 | 站点数 | 形状 |
|---|---|---|---|
| A | **memcpy 补丁** `0x10033340` | **306** | 用一段字节覆盖 M2Server 代码 |
| B | **立即数写入** 内联 `VirtualProtect` + `mov [绝对地址], reg` | **145** | 把配置数值写进某条指令的立即数操作数 |
| C | **detour/蹦床** `0x10032FD0`（30 处 push）/ `0x10032CC0`（64 处） | 64+ | `VirtualAlloc(0x400, MEM_COMMIT, PAGE_EXECUTE_READWRITE)` 后组装字节码，含 `0xE8`/`0xE9` 重定位修正 |

A 与 B 可完全还原；**C 的桩体是运行时汇编出来的**，本轮不解，见 §5。

### 1.2 补丁原语 `0x10033340` 逐字节

调用点形状（以 `屏蔽自动绑定` `0x100BF513` 为准）：

```
0x100BF513  83 EC 0C                    sub esp, 0xC          ; 按值传入的 12 字节 vector
0x100BF516  C6 45 B3 00                 mov byte [ebp-0x4D], 0 ; ← 载荷
0x100BF52F  68 57 DC 74 00              push 0x74DC57         ; va_end
0x100BF534  68 57 DC 74 00              push 0x74DC57         ; va_begin
0x100BF539  6A 01                       push 1                ; len
0x100BF53B  50                          push eax              ; &载荷
0x100BF540  E8 FB 3D F7 FF              call 0x10033340
```

被调方：

```
0x10033381  call 0x100329F0 / cmp eax,0x64 / je bail   ; 全局"允许打补丁"状态 ≠ 100
0x1003338F  push 1 / call 0x11513568 / test al,al / jne bail
0x100333B3  call 0x10032A50                           ; VirtualProtect(va, len+1, 0x40, &old)
0x100333C2  push edi(len) / push ebx(src) / push [ebp-0x20](va)
0x100333C5  call 0x10223FD0                           ; memcpy
0x1003340F  call 0x10032A50                           ; 恢复保护
```

### 1.3 配置键 → 结构字段（有一个必踩的坑）

装载函数 `0x100AF8A0` 的循环体形如：

```
call 0x100DFE40        ; eax = value(K[n-1])
push end(K[n]) / push K[n]
mov [edi+OFF], eax     ; ← 存的是 K[n-1] 的值，不是 K[n] 的
call 0x100E0BE0        ; find(K[n])
call 0x100DFE40        ; eax = value(K[n])
```

**存储指令滞后一轮。** 按"push 键 → 紧邻的 store"配对会让整张表错位一位。
正确读法是"push K[n] 之后的那个 store 属于 K[n-1]"，等价地"K 的字段 = 它之后
第二个 store"。用补丁臂的守卫回验通过：

| 键 | 键串 VA | 字段 | 补丁臂守卫 |
|---|---|---|---|
| `穿人穿怪` | `0x102B03C4` | `[this+0x172C]` | — |
| `禁止交易地图` | `0x102B03D0` | `[this+0x828]` | — |
| `行会显示` | `0x102B03F0` | `[this+0x9D0]` | `0x100AAC8B cmp [edi+0x9D0],0` ✓ |
| `禁止宝宝休息` | `0x102B03E0` | `[this+0x948]` | `0x100AAB35 cmp [edi+0x948],0` ✓ |
| `地面物品消失时间` | `0x102B0418` | `[this+0xB68]`（`+0xB6C` = 原始串） | `0x100AAF5B cmp [edi+0xB68],0` ✓ |
| `关闭摆摊` | `0x102B0490` | `[this+0xE98]` | `0x100AD0D9 cmp [edi+0xE98],0` ✓ |
| `屏蔽排行榜` | `0x102B070C` | `[esi+0x438]`（另一张表 `0x100BA940`） | — |

另有一个**已生效状态**字段族在 `[0x1031C4BC]+0x7XX`：置 `0x64`(=100) 表示已应用，
`0` 表示未应用。开关臂形状恒为
`cmp [switch],0 / je 反向臂 → cmp [state],0 / jg 跳过 → 打补丁 → mov [state],0x64 → 打状态标签`。

### 1.4 状态标签就是功能名

`0x100F018C(ecx=控件字段, 字符串)` 在每组补丁之后写 `"XXX(已启动)"` / `"XXX(未启动)"`。
**标签归属于它之前的那组补丁**（先打补丁，再改按钮文字）。
第一版提取器按"之前的标签"配对，把启用臂和还原臂整体互换了；`屏蔽自动绑定`
写 `00` 的那组才是启用（还原臂写 `01`），据此修正。

### 3.3 `关闭摆摊` —— 提交 `230a6e8c`

| 项 | 值 |
|---|---|
| 键 VA | `0x102B0490`；字段 `[this+0xE98]`；状态 `[0x1031C4BC+0x774]` |
| 类型 | **patch 站点**（memcpy，1 字节） |
| 消费点 VA（插件） | 启用 `0x100AD12A`；还原 `0x100AD1AE` |
| 目标 VA（M2） | `0x6E7C38` `55 → C3` |

```
0x100AD0D9  cmp dword [edi+0xE98], 0
0x100AD0E2  cmp dword [eax+0x774], 0
0x100AD0EE  C6 85 13 EF FF FF C3        ; 载荷 = C3
0x100AD113  push 0x6E7C38 ×2 / push 1 / push &载荷
0x100AD12A  call 0x10033340

`0x6E7C38` 即 `sub_6E7C38`，本仓 `NativeStallWriteTransaction.cs:21` 已命名为
`CM_START_STALL(4424)` 的函数体。原生序言与 `C3` 跳过的内容：

```

006E7C41  call 0x6E78D4        ; 摊主前置判定
006E7C58  call 0x7684A0        ; MapAllowsStall

⇒ 入口 `C3` ⇒ **直接返回，不查地图、不跑阶梯、不发任何 SM 4424**。

**删物/发币论证（任务要求 5）**：C# 侧的提前返回放在
`manager.GetOrCreate(...)` **之前**，因此不建记录、不读金币、不落库、不发包，

那会发出一个原生 `ret` 根本不会发的回包。
（现状仍然休眠：`TryRouteNativeStallWrite` 先被 `NativeStallWriteGate.Enabled` 短路。）

## 4. 方法论警告：没有未打补丁的 M2Server 基线

| 事实 | 证据 |
|---|---|
| 磁盘 `M2Server.exe` 啃不动 | `2ad31a8a…`，7,774,208 B，节表 `CODE VA 0x401000 VSZ 0x3A00D0 **RAW 0x0/0x0**`，载荷在 `.vmp0`/`.vmp1` |
| 唯一可读的 M2Server 是活进程转储 | `staging\_reunpack_work\flat_image.bin` |
| 两份独立转储的**代码区完全一致** | 与 `yanshen208_strparam_runtime_dump_20260719\M2Server_exe.memory.bin` 相比，2,307 处差异**全部 ≥ `0x7A2008`（DATA 段）**，`0x401000..0x7A0000` 内差异 **0** |
| 但插件的"复位表"与转储对不上 | 96 个随机极品槽里 **24 个**不一致，且**两个方向都有**（转储 20 / 复位 30，也有转储 30 / 复位 20） |
| 转储不像是"已应用"态 | 生产配置 `屏蔽自动绑定 = 1`，而 `0x74DC57..0x74DDEF` 存的是 `01` —— 正是**停用臂**写的值；若已应用应为 `00` |

**结论**：转储更像是**未应用**态，而插件的复位表**不是可靠的 stock 判据**
（它可能编码的是作者面向另一份 M2Server 构建的默认值）。
报告里凡出现 `orig`/`dumped` 字样，一律指**转储当时的字节**，不等于出厂字节。
需要真正的 stock 基线时，必须另抓一份"插件未加载"的 M2Server 转储。

## 7. 对既有材料的纠错

1. `TBaseObject.ViewRange.cs` 的注释说 `0x927C0` "there is no config knob for it in the image"
   —— **M2Server 里确实没有，但插件加了一个**：`地面物品消失时间_时间` 经
   `atoi × 1000` 直接改写 `0x77A3FF` 这个立即数。该文件的实现本来就已经尊重插件覆盖，
   只是注释低估了机制。
2. `YanshenFixedReplicaPanels.cs:283` 的界面提示 "单位秒 默认600" 指的是**关掉开关时**的
   原生行为（`0x927C0`）；插件在键缺失时用的是 **300**（`0x100B01AA`）。两个数都真实，含义不同。
3. `ys_gui_inventory_20260813.md` §5.1 把 `行会显示` 计入 IMPLEMENTED，依据是
   `GetCreatureAttr` 里的 `Enabled("行会显示")` 门。那是**脚本 API 门**，
   与该开关的字节行为（`GetShowName` 两处 `je` 变 NOP）无关。两者可以并存，但不该互相顶替。
