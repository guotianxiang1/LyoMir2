# 随机极品：96 个 GUI 键 → 宿主立即数的完整映射

生成脚本 `tools/ys_extreme_map.py`（可复跑），产物 `docs/ys_extreme_map.tsv`。
基址：插件转储 `0x10000000`，M2Server `flat_image.bin` `0x400000`。

本文解掉的是 `ys_gui_impl2_20260813.md` §5 的 BLOCKED #6
——「96 槽立即数族的驱动键名尚未与 `config.json` 对上」。现在 96/96 全部对上，
而且键名与宿主语义**逐字吻合**，不是靠位置猜的。

## 1. 为什么这一块值得优先做

`盘古4` 是 380 键里最大的一页（98 键），其中 **92 键生产已开启但 C# 无行为**，
占「生产已开启且无行为」总数 172 的 **53%**。而它控制的是**掉落装备的属性点数**，
直接决定物品价值。

## 2. 键的落点：两跳

### 2.1 配置读取 → 单例字符串字段

配置装载器（`0x100C6DE0..0x100CB800`）把每个键读成 std::string，存进
**`[0x1031C5BC] + OFF`**。注意这个单例与开关用的 `0x1031C4BC` **不是同一个**。

```
0x100c6e0e  68 F4 0A 2B 10   push 0x102b0af4      ; "武器最高点数_攻击_值"
0x100c6e21  80 78 08 00      cmp byte [eax+8], 0  ; 键存在？
0x100c6e25  0F 84 BF 00 00 00 je  ...             ; 不存在则整段跳过
0x100c6e51  A1 BC C5 31 10   mov eax,[0x1031c5bc]
0x100c6e56  05 10 0F 00 00   add eax, 0xf10       ; ← 该键的字段偏移
```

96 个偏移构成一条**连续的 24 字节网格**（`std::string` 大小）
`0xF10 .. 0x17F8`，规律是：

| 层级 | 步长 |
|---|---|
| 装备类（武器/衣服/头盔/项链/手镯/戒指） | `0x180` |
| 属性（攻击/魔法/道术/攻速/准确） | `0x48` |
| 组内（最高点数 / 点数几率 / 属性几率） | `0x18` |
| `最随机性_极品` | 装备基址 `+0x168` |

装备基址依次 `0xF10 / 0x1090 / 0x1210 / 0x1390 / 0x1510 / 0x1690`。
脚本对 96 个键逐个回查装载器验证，**95/96 命中**（`戒指点数几率_魔法_值` 的
装载器形状略有出入，其余两条独立判据仍然覆盖它）。

### 2.2 应用臂 → 直接改写宿主 `.text`

`sub_100BF430`（盘古4 的 apply 函数）是一段展开 96 次的循环：

```
for i in 0..95:
    v = atoi(text[i])
    if v > 0 and v != cache[i]:  mov [hostVA_i], v     ← 4 字节直写 M2Server .text
    cache[i] = v                                        ← mov [esi+0x2EC+4i], eax
    singleton.str[i].assign(text[i])                    ← add eax,OFF_i ; assign
```

**注意补丁手段**：既不是 memcpy 也不是 trampoline，而是 `mov dword [绝对地址], eax`
直接写进宿主代码段的立即数字段。只扫 memcpy/`0x10033340` 会完全漏掉这 96 处。

样例（`武器点数几率_攻击_值`，字段 `0xF10`）：

```
0x100bfe7c  A3 0F 09 76 00   mov [0x76090f], eax     ; 宿主 0x76090E BA 14 00 00 00  mov edx,0x14
0x100bfe9a  89 86 F0 02 00 00 mov [esi+0x2f0], eax   ; 已应用缓存
0x100bfea0  8B 8E 70 01 00 00 mov ecx,[esi+0x170]    ; 下一个键的 GUI 文本指针
0x100bfead  05 28 0F 00 00   add eax, 0xf28          ; 下一个键的字段
```

**相位判定**（这里错一格就整张表错位，踩过一次）：宿主写入与 cache 写入排在
它所属那一槽的 `add eax,OFF` **之前**。两条独立判据确认：

1. cache 偏移必须解出严格网格 `0x2EC + 4i`（i=0..95）——脚本里是断言，错位即 BROKEN。
2. 六个装备类各自的 16 个宿主 VA 必须落在一个连续块内（实测宽度
   `0xC9..0xE8`，仅 `衣服` 例外，见 §4）。

### 2.3 可观测契约

应用臂是 `test eax,eax / jle 跳过`——**值 ≤ 0 就不打补丁，宿主保持出厂立即数**。
这与总纲 §5.1.0.4「消费端一律 ≤0 整段跳过」一致。生产配置里
`武器最高点数_攻击_值`、`手镯最高点数_攻击/魔法_值`、`戒指最高点数_攻击/魔法_值`
都是空串 → 这几槽保持出厂值，**不是 0**。

## 3. 宿主语义：键名与代码逐字吻合

`sub_4C707C(eax=N, edx=P)` 不是「区间随机」，是**计数器**：

```
004c708c  4B              dec ebx           ; ebx = N-1
004c708f  7C 12           jl  return 0      ; N<=0 → 0
004c7091  43              inc ebx
004c7092  8B C6           mov eax,esi       ; esi = P
004c7094  E8 B3 CA F3 FF  call 0x403B4C     ; Random(P)
004c7099  85 C0 / 75 06   test eax,eax / jne
004c709d  FF 45 FC        inc result
004c70a1  75 EF           jne loop          ; 共 N 次
```

即 **N 次伯努利试验、每次 `Random(P)==0` 命中，返回命中次数**。于是：

| 配置键 | 宿主角色 | 出厂值 |
|---|---|---|
| `最高点数_X_值` | `sub_4C707C` 的 **N**（试验次数 = 点数上限） | 6（武器非攻击位 12） |
| `点数几率_X_值` | `sub_4C707C` 的 **P**（每点 `1/P` 命中） | 20（武器非攻击位 15） |
| `属性几率_X_值` | 该属性是否写入的闸门 `Random(P)==0` | 0x14 / 0x1E / 0x28 |
| `最随机性_极品_值` | 整件装备是否参与随机的闸门 `Random(P)==0` | 10（戒指 9） |

武器完整反汇编（`sub_7608D4`，基址 `0x400000`）：

```
007608d4  55 8B EC 53 56 57        ; RandomSuperior(eax=UserItem, dl=flag)
007608e2  E8 15 36 02 00  call 0x783EFC        ; 耐久抖动 Dura = DuraMax*(Random(0x50)+0x14)/100
007608e7  84 DB / 0F 85   test bl,bl / jne 退出 ; flag 非 0 直接退出
007608ef  B8 0A 00 00 00  mov eax,0xA          ; ← 武器最随机性_极品_值（生产 80）
007608f4  E8 53 32 CA FF  call 0x403B4C        ; Random
007608f9  85 C0 / 0F 85   test eax,eax / jne 退出
00760901  8B 47 1C        mov eax,[edi+0x1C]   ; StdItem
00760904  F6 40 02 40     test byte [eax+2],0x40 ; StdMode 位 0x40 = 允许随机极品属性
00760908  0F 84           je 退出
; ---- 攻击 ----
0076090e  BA 14 00 00 00  mov edx,0x14         ; ← 武器点数几率_攻击_值（生产 5）
00760913  B8 06 00 00 00  mov eax,6            ; ← 武器最高点数_攻击_值（生产空 → 保持 6）
00760918  E8 5F 67 D6 FF  call 0x4C707C        ; esi = 命中次数
0076091f  B8 1E 00 00 00  mov eax,0x1E         ; ← 武器属性几率_攻击_值（生产 10）
00760924  E8 23 32 CA FF  call 0x403B4C
00760929  85 C0 / 75 06   test eax,eax / jne 跳过
0076092d  8B C6 / 40      mov eax,esi / inc eax
00760930  88 47 2A        mov [edi+0x2A],al    ; 写属性槽（= n+1，最小 1）
; ---- 魔法/道术/攻速/准确 同形 ----
```

**RNG 顺序很关键**：`sub_4C707C` 在闸门 `Random(属性几率)` **之前**调用，
即使闸门不通过，那 N 次抽取也已经消耗了随机序列。复刻时不能把它挪到闸门里面，
否则整条掉落 RNG 序列偏移（参照 `AuditTools/NativeDropRngSequenceCheck`）。

## 4. 六个例程都是 VMT 槽 19 的虚方法

| 装备类 | 函数起点 | 所在 VMT（索引恒为 19） |
|---|---|---|
| 武器 | `0x7608D4` | `0x75D1F4` `0x75D2E8` `0x75D3E8`（3 个子类） |
| 衣服 | `0x7639DC` | `0x75CBF8` `0x75CCEC` `0x75CDE4` `0x75CEF0` `0x75CFF0`（5 个子类） |
| 头盔 | `0x7611C8` | `0x75D6C4` |
| 项链 | `0x76178C` | `0x75D7B4` |
| 戒指 | `0x761CC4` | `0x75D8AC` |
| 手镯 | `0x7625BC` | `0x75D99C` |

共 12 个物品类共享同一个虚槽。`衣服` 的宿主 VA 之所以横跨
`0x7639F3` 与 `0x783F55..0x783FF2`（宽度 0x205FF，其余五类只有 ~0xCA），
是因为它的实现被拆成两个函数：`0x7639DC` 只做耐久抖动 + `最随机性_极品` 闸门，
属性主体在 `0x783F40`（`0x763A02 call 0x783F40`）。**这不是提取错误。**

## 5. 交付状态

- 96/96 键 → 宿主 VA + 宿主指令 + 出厂立即数 + 生产值，已在
  `docs/ys_extreme_map.tsv`。
- 算法语义已完整（§3），RNG 顺序已确定。
- **仍缺的一环**：虚槽 19 的调用点没有定位。`call [reg+0x4C]` 在 M2Server 里
  有 112 处，需要按对象类型过滤才能定出「掉落时谁调它」。
  C# 侧 `GoodItem.RandomUpgradeItem`（`GameSvr/Items/GoodItem.cs:164`）**不是**它
  ——常量与结构都不同（无 `最随机性` 总闸门、无 `StdMode & 0x40` 判定、
  且带 DuraMax 提升）。所以这 96 键在 C# 里属于**机制层面完全缺失**，
  不是接线问题；按本仓既定标准（无落点不实现），实现前需先定位调用点。
