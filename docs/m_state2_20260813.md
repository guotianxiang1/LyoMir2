## 1. 原生的真实存储形状

**一条链表 + 一张位图，没有第二份存储，单位一律毫秒。**

### 1.1 记录结构（18 字节）

分配器 `0x764E00` 与释放器 `0x764E10` 都写死 `0x12`：

```
0x764E00  B8 12 00 00 00     mov  eax, 0x12
0x764E08  E8 93 E1 C9 FF     call 0x402FA0        ; GetMem
0x764E10  BA 12 00 00 00     mov  edx, 0x12
0x764E18  E8 B3 E1 C9 FF     call 0x402FD0        ; FreeMem

|---|---|---|---|

| +0x01 | byte | internalType | `0x773164 88 58 01 mov [eax+1], bl` |
| +0x02 | dword | 剩余**毫秒** | `0x77315E 89 50 02 mov [eax+2], edx`（来自 `[ebp-4]`） |

`FindState` `0x773B98`：

```
0x773BB1  E8 AA ED FF FF        call 0x772960        ; HasState

### 1.4 过期只有一处：500 毫秒扫描

`0x772FD0`：

```
0x772FE4  2B 83 E0 00 00 00     sub  eax, [ebx+0xE0]
0x772FEA  3D F4 01 00 00        cmp  eax, 0x1F4        ; 500
0x772FEF  0F 82 AF 00 00 00     jb   0x7730A4          ; 无符号 < 500 跳过
0x772FF5  89 B3 E0 00 00 00     mov  [ebx+0xE0], esi   ; 硬置位
```

逐节点步进 `0x7730AC`（`VMT+0x58`）：

```
0x7730B1  83 78 02 FF           cmp  dword [eax+2], -1  ; 永久哨兵
0x7730B5  74 13                 je   -> 不过期
0x7730B9  2B 50 06              sub  edx, [eax+6]       ; now - lastTick
0x7730BC  29 50 02              sub  [eax+2], edx
0x7730BF  89 48 06              mov  [eax+6], ecx
0x7730C2  83 78 02 00           cmp  dword [eax+2], 0
0x7730C6  7F 02                 jg   -> 存活            ; 【有符号】
0x7730C8  B3 01                 mov  bl, 1              ; 过期
```

扫描分两趟：先把过期节点从链上摘下并 `btr` 清位、头插进临时链（因此顺序反转），
再遍历临时链调 `VMT+0x5C`（state-lost）并 `0x764E10` 释放。

> **结论：原生没有任何"12 槽秒级数组"。** C# 的 `ushort[12]` 是外来物。

### 2.3 落地方案与结果

`m_wStatusTimeArr` 改成 `LegacyStatusTimeView` 转发视图（`readonly struct`，
只持有 owner 引用，无存储），并从**字段改成属性**——这样任何遗漏的赋值点都会
编译失败，从机制上避免"改一半"。

- 读：走位集门控的 `FindTimedAbilityInternal`（对齐 `0x773BB1`），
  毫秒 → 秒**向上取整**。若截断，剩 500ms 的节点会读成 0，
  把那 60 处 `slot == 0` 行动门全部误放行。
- 写：直接改节点 `RemainingMilliseconds`。不能走 AddState——
  `0x773117 cmp edi,eax / jle` 只在 value 变大时刷新、
  `0x773140 cmp eax,[ebp-4] / jge` 只在时长变长时延长，
  而 legacy 有大量 `slot = 1`（"下一秒失效"）语义，走 AddState 会被吞掉。
  仅新建节点时走 AddState，以便 `0x772F84` 门、位集、gained 派发照常执行。
- 永久：`>= 60000` ↔ 节点 `-1`（`0x7730B1 cmp dword [eax+2],-1 / je`）。
- 删除 `m_dwStatusArrTick` 与每秒倒计时循环；其 4 个副作用移入
  `OnNativeTimedStateLost`，由两条摘除路径调用。
- `GetCharStatus` 不再叠 overlay。它原先用另一套过期时钟重算
  `SetNativeActiveState` 已经拥有的 bit 20..31，导致被清掉的状态在下一次重建时复活。
- 持久化三条路径同时改：记录布局不变（12 × ushort 秒，槽 i = state 31-i），
  装载走 `CopyFrom`、存档走 `ToArray`，两端都仍清槽 11。
  装载与两条清空路径**静默**建/拆节点，与它们替换掉的裸数组赋值一致
  （这些调用点都在角色尚未进图时执行）。

新增 `AuditTools/LegacyStatusSlotAuthorityCheck` 钉住整份契约。

## 3. 重算位图（复核结论：**原本就是对的**）

```
0x773254  80 C2 F8              add  dl, 0xF8      ; (internalType - 8) & 0xFF
0x773257  80 FA 67              cmp  dl, 0x67
0x77325A  77 0A                 ja   0x773266
0x77325C  83 E2 7F              and  edx, 0x7F
0x77325F  0F A3 15 6C 32 77 00  bt   [0x77326C], edx
0x773266  0F 92 C0              setb al
```

`0x77326C` 处 14 字节，逐字节读出：

```
40 60 00 FF DF 01 00 00 78 20 7C BF 01 00
```

- C# `NativeRecalcBitmap` 与之**逐字节相同**，第 5 字节确为 `0x01`（不是 `0x11`）。
- `NativeRecalcBitmapBias = 8` 正确。`add dl,0xF8` 是**字节加**会回绕，
  所以 internalType 0..7 落在 0xF8..0xFF，全部 `> 0x67` 出界——
  C# 的 `biased < 0` 分支等价。
- 按 -8 偏置解出 37 位：
  14, 21, 22, 32..44, 46, 47, 48, 75, 76, 77, 78, 85, 90..94, 96..101, 103, 104。

**独立佐证**：这 37 个正好是 §4 gained 派发表里所有"改属性"的 state
（21 抗魔力、22 防御力、32..41 六组上下限/攻速/生命/魔法/敏捷/魔躲、
75..78 抗性与刺术、90..94、96..101、103、104）。
不加偏置会解出 24..31，那是中毒/石化/冰冻带，一个属性都不改。

`AuditTools/State41RecalcBitmapCheck` 原先断言的恰是**未加偏置的错误形状**
（要求源码写 `internalType / 8`，并断言 "state 26 在集合内"），
即 REPLICATION_RULES 4.17 说的"审计工具本身是坏的"。已重写为从字节重放判定。

### 4.3 上限与叠加规则

- 上限：`internalType > 0x6F`（111）时 `bt`/`bts`/`btr` 全部跳过
  （`cmp ..,0x6F / ja`）。注意**节点仍会入链**，只是位不置——
  由于 `FindState` 先查位，这种节点永远查不到，等于泄漏。
- 同类型再次施加（`AddState` `0x773103` 起）：
  - 找到已有节点 → `[node] = flag`（`0x77310F`，**无条件覆盖**）
  - `0x773117 cmp edi,eax / 7E jle` → 新 value **>** 旧 value 才刷新，
    并同时改写时长（`0x773121` 写 `[node+2]`、`0x773127` 写 `[node+0xA]`）并调 `VMT+0x60`
  - `0x773136 cmp edi,eax / 75 jne` → value **相等**时，
    `0x773143 cmp eax,[ebp-4] / 7D jge` 只在新时长更长时延长，且**不**调 `VMT+0x60`
  - value 变小 → **完全拒绝**（既不刷新时长也不改值）
  - 因此规则是「取较大 value，同 value 取较长时长」，不是简单刷新也不是叠加。
- 到期清除：见 §1.4。位清除与摘链在第一趟同时完成，回调在第二趟，
  顺序因头插而反转（最早过期的先回调）。

### 5.2 周期伤害：2500 毫秒，四档**互斥**

`0x76BD33`-`0x76BE1C`：

0x76BD3E  0F 82 DC 00 00 00     jb   0x76BE20        ; 无符号 <2500 跳过

- 四档是 `if/else-if`，**一个 tick 只服务一档**，优先级 `0x06 > 0x01 > 0x1C > 0x1F`。

- `0x4C700C` 是 **MIN**（`cmp edx,eax / 7F jg`），紧邻的 `0x4C7004` 才是 MAX
  （`cmp edx,eax / 7C jl`）。落错入口会得到反义函数。
- 上限常量是 `0x4C4B40` = **5,000,000**，不是 1,000,000。
- C# `TryResolveNativePoisonTickDamage` 与之逐条对应，**FAITHFUL**。

### 5.3 红毒档位与石化

- 红毒 = state 30。伤害放大档由**节点 value**（level）选，不是位：
  `0x767A94 HasState(0x1E)` → `0x767AA1 GetStateValue(0x1E)` →
  `0x767AAA cmp eax,4 / 75 jne` → 等于 4 走 ×1.25（float32 `0x767B3C`），
  否则 ×1.2（ext80 `0x767B40`）。C# 由 `RecordNativeRedPoisonLevel` 落 level。
- 石化 = state 26，另有一套免疫时限（`Self+0x3A4`，见 §4.4 第二段），
  且被 state 16 与 state 18 各自封锁，属于与普通毒完全不同的一类。
- 解毒（`MagicManager.cs:571-583`）把槽置 1 = "下一拍失效"，收敛后语义不变。
