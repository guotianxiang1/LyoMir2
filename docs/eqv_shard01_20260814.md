## 已记录分歧（属大改/平台限制，本轮不动手，仅报告）

**① m_nRebate 额外舍入阶段（影响 ECON-03/06 的“完全等价”）**
- 现状：`GetUserPrice`(Merchant.cs:1187-1188) 与 `GetSellItemPrice`(2107-2108) 在 `m_nRebate != 100` 时多做一次 `Round(result*m_nRebate/100.0)`。原生费率段 sub_640208 **无此步**。
- 根因（C# 注释已详证）：原生只有**一个**费率字段 +0x468；PAS `SetRebate`(名字串 0x739EF4、注册点 0x738E34、处理器 sub_647438 写 +0x468) 与费率段读的是**同一字段**。C# 拆成 m_nPriceRate + m_nRebate 两个权威（违 §4.18）。
- 影响：**m_nRebate 默认 100，默认配置下该分支不执行**，故默认行为等价；仅当脚本调用 `setrebate` 时偏离。
- 正确修法（跨 PasApiBridge，须单列任务）：让 `setrebate`(PasApiBridge.cs:5590) 改写 m_nPriceRate 并补 `<=0`/`>=0xFFFF` 复位 100 校验，然后删两处 rebate 阶段。**单删阶段会使 setrebate 变空操作，比现状更糟**，故不动。

**② 80-bit 扩展精度（ECON-08）**：C# 无 long double，用 double 复刻 0.8/1.1/0.05。双舍入风险为纯 C# 不可消除的平台限制；对现实价格区间实际不可观测，但严格意义非逐位等价。记录备查，无小修法。

**③ 数量门谓词（ECON-12）**：C# 用 `IsPileItem(StdMode>=150+运行时类名)` 映射原生「实例+0x14==7」。TUserItem 无原生内存布局的 +0x14 KIND 字节，逐字节复制需新增字段（架构改动）。当前映射有构造器证据支撑且全项目一致，判 FAITHFUL 带注。
