# 口径定义（唯一权威）

生成时间：2026-08-18。本文件是项目中**唯一**允许定义完成度口径的地方。

## 为什么需要这份文件

2026-08-18 的机械普查发现：757 份文档中有 224 份含进度断言，抽取出 **23 个互不相同的"完成度"百分比**，范围 60.0% ~ 100.0%。

关键发现：**这些数字大部分不是笔误，而是分母相同（754）、计数规则不同**。举例（全部出自 2026-08-14 同一天）：

| 数字 | 出处 | 实际公式 |
|---|---|---|
| 89.4% | `completeness_audit_20260814.md:21` | (FAITHFUL + FIXED) / 754 |
| 91.9% | `completeness_audit_v2_20260814.md:30` | 同上口径，重算后 693/754 |
| 94.16% | `completeness_refresh_20260814.md:55` | (648 + 62) / 754 |
| 97.0% | `completeness_audit_20260814.md:25` | (FAITHFUL + FIXED + BLOCKED + FAIL-CLOSED) / 754 |
| 99.1% | `completeness_audit_v2_20260814.md:32` | 把 54 条不可证/外部依赖全算可交付 |
| 86.6% | `completeness_audit_v2_20260814.md:34` | 剔除 40 条非 Tier-1 证据的 FAITHFUL |

因为没有命名规则，任何人都能挑一个对自己有利的数字引用，且每个都"有出处"。`completeness_audit_v2_20260814.md:37` 自己就写了「广义 99.1% 这个数字不要单独引用」——说明当时已经意识到问题，但没有从制度上解决。

## 命名口径

以下四个口径**必须带名字引用**，禁止裸写"完成度 X%"。

### M1 严格证据完成度 (Strict)

```
M1 = (FAITHFUL + FIXED) / TOTAL
```

- 计入：有 Tier-1 逐字节证据、且 C# 行为与原版一致的契约
- 不计入：BLOCKED、UNPROVEN、FAIL-CLOSED、DORMANT、MISSING、DIVERGENT
- 用途：**对外汇报唯一允许的默认口径**
- 性质：最保守，只认已证明

### M2 含缺失等价完成度 (Strict + Proven-Absence)

```
M2 = (FAITHFUL + FIXED + PROVEN_ABSENT) / TOTAL
```

- `PROVEN_ABSENT` = 已用二进制普查证明"原版根本没有这个行为"，因此 C# 不实现即等价
- 举证要求：必须附 token 普查或全代码段扫描证据，不能只写"没找到"
- 用途：技术讨论
- 性质：比 M1 宽，但每一条增量都要有反向存在性证明

### M3 边界安全度 (Boundary-Safe)

```
M3 = (FAITHFUL + FIXED + PROVEN_ABSENT + FAIL_CLOSED) / TOTAL
```

- `FAIL_CLOSED` = 证据不足，C# 选择保守拒绝而非猜测行为
- 用途：评估"会不会因为猜错行为而产生脏数据"
- **性质：不是功能完成度。** FAIL_CLOSED 项在生产中表现为功能缺失或拒绝服务
- 禁止：用 M3 回答"复刻完成了多少"

### M4 生产可达完成度 (Production-Reachable)

```
M4 = PRODUCTION / TOTAL
```

- `PRODUCTION` = 从生产入口（Main / 消息派发 / 定时器 / 脚本 API）实际可达，且非 DORMANT
- 判据：调用链可追溯到入口，且无 `DormantOperation` / `NO-GO` 守卫
- 用途：回答"现在启动服务器，玩家能用到多少"
- 性质：**唯一能用于上线决策的口径**

## 状态标签（每个契约恰好一个）

| 标签 | 含义 | 计入 M1 | M2 | M3 | M4 |
|---|---|:-:|:-:|:-:|:-:|
| `FAITHFUL` | Tier-1 证据 + 行为一致 | ✅ | ✅ | ✅ | 取决于接线 |
| `FIXED` | 曾背离，已修复并验证 | ✅ | ✅ | ✅ | 取决于接线 |
| `PROVEN_ABSENT` | 已证原版无此行为 | ❌ | ✅ | ✅ | N/A |
| `FAIL_CLOSED` | 证据不足，保守拒绝 | ❌ | ❌ | ✅ | ❌ |
| `DORMANT` | 代码完整但未接生产 | ❌ | ❌ | ❌ | ❌ |
| `BLOCKED` | 外部依赖缺失（VMP/DBServer/MySQL） | ❌ | ❌ | ❌ | ❌ |
| `UNPROVEN` | 有代码，未验证 | ❌ | ❌ | ❌ | ❌ |
| `MISSING` | 原版有，C# 无 | ❌ | ❌ | ❌ | ❌ |
| `DIVERGENT` | C# 行为与原版不同 | ❌ | ❌ | ❌ | ❌ |
| `STUB` | 抛异常的占位 | ❌ | ❌ | ❌ | ❌ |

## 引用规则

1. **必须带口径名**：写 `M1 = 94.2%`，不写 `完成度 94.2%`
2. **必须带基线**：附 commit SHA 和日期
3. **必须带分母来源**：754 这个数字本身要指向账本文件
4. **禁止跨口径比较**：M3 的 97% 不能和 M1 的 89% 放在一起说"提升了"
5. **禁止把 M1~M3 当上线依据**：上线只看 M4 + 全栈集成测试

## 分母的诚实性

754 这个分母**本身不完整**。`completeness_refresh_20260814.md:840` 已记录：跨服 OthGs 有 8 个新分歧 ident 未补契约号。

因此所有口径都应表述为"**已登记 754 项中的** X%"，而不是"M2 复刻的 X%"。原版战神引擎的真实行为总量未知且不可枚举。
