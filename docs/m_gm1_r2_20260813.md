## 任务一：`NativeType43EarthFireCompatCheck` 的 `gowgo`

### 定性：**审计钉错了**（不是产品把覆盖做早了）

审计读的是**类型上的** `[GameCommand]` 源名：

```
typeof(UserMoveXYCommand).GetCustomAttribute<GameCommandAttribute>().Name
Equal("UserMoveXY", …, "UserMove registration source name")
```

`ApplyNativeFormGmCommandIni` 只改实例的 `GameCommand.Name` 和 `CommandMaps`，**不会**改 `GetCustomAttribute` 读到的元数据。所以失败 `expected=UserMoveXY, actual=gowgo` 来自把属性改成原生表内名 `gowgo`（`9a285dd8`），不是 ini 覆盖把源名改成了生产别名 `sdgo`。

### 原生：覆盖发生在 **Add 之前**，哈希表只登记一次

`0x0062253C` 循环（步长 `0x120`，430 条）：

```

00622556  e8 f5 96 de ff        call 0x40BC50     ; UpperCase → [ebp-8] 哈希键
0062255E  8b 43 18              mov eax,[ebx+0x18]; 索引
00622561  e8 36 a3 de ff        call 0x40C89C     ; IntToStr(索引)
0062256E  ff 51 58              call [ecx+0x58]   ; TStringList.IndexOf
00622575  7c 18                 jl  0x62258F      ; miss → 保留内置名
0062257F  e8 c4 55 e0 ff        call 0x427B48     ; hit → 取 ini 值
0062258A  e8 c1 96 de ff        call 0x40BC50     ; UpperCase(值) 覆盖 [ebp-8]
```

`0x006225FC` 长串 len=17：`FormGMCommand.ini`。

「注册名」= 表 ShortString（idx 29 = `gowgo`，记录 `0x007B65D4` `05 67 6f 77 67 6f`）。
运行时哈希键 = ini 命中则覆盖后的名，未命中则仍是 `GOWGO`。生产 `29=sdgo` 时哈希表里**没有** `gowgo`。

C# 已改为：发 `RM_PASSWORD`、绿字「请输入密码」、置 `m_boWaitSuperGmPassword`（对应 +0x674）。**不再写权限 10，不再开无敌/隐身/管理模式。**

### BLOCKED（SuperGm 密码核对）

`mov byte [obj+0x674],1` 是全镜像对该**字节**的唯一写入。扫 `74 06 00 00` 的其它命中是 DWORD 英雄字段或 `jmp rel32` 假阳性，**没有** `cmp/test/movzx byte [r+0x674]`。密码提交走 `CM_PASSWORD` → `ProcessClientPassword`；在没有仓库锁标志时原生/C# 都会把输入丢掉。核对密码、升权限的那一跳仍未找到，保持 fail-closed（不升权）。

## 任务二.3 `0x768BE0` vs `AddGameDataLog`

**不是 1:1。**

`sub_768BE0`（`0x00768BE0`，`ret 0xC`）把三个栈参 + 玩家字段交给 `sub_79D3D8`，打出 **0xBC 字节二进制记录**：

```
00768BFE  66 8b 83 2c 01 00 00  mov ax,[ebx+0x12C]  ; X
00768C06  66 8b 83 30 01 00 00  mov ax,[ebx+0x130]  ; Y
00768C11  lea edx,[ebx+0x106]                       ; 地图名 ShortString
00768C30  lea edx,[ebx+0x115]                       ; 角色名 ShortString
0079D40D  C7 07 77 BB AA 33                         ; magic 0x33AABB77
0079D41B  66 C7 47 06 BC 00                         ; 记录长 0xBC
0079D421  88 5F 1D                                  ; +0x1D = 类型字节
```

`79D3D8` 字段：

| 偏移 | 宽 | 内容 |
|---|---|---|
| +0 | 4 | `0x33AABB77` |
| +8 | 20 | 角色名 |
| +0x1D | 1 | 类型（Make 为 5） |
| +0x20 | 4 | X（obj+0x12C） |
| +0x24 | 4 | Y（obj+0x130） |
| +0x28 | 20 | 地图名 |
| +0x3D | 20 | 物品名 |
| +0x54 | 4 | MakeIndex |
| +0x58 | 4 | 数量（堆叠=Dura，否则 1） |
| +0x5C | 100 | 末列（Make 为 `"0"`） |

C# `AddGameDataLog` 是 **tab 文本**，既有约定（`WritePileItemLog` / 定点石）写成：

`type \t map \t X \t Y \t char \t name \t MakeIndex \t count \t "0"`

与二进制记录的列序（char, type, X, Y, map, …）不同，也不是 `0x33AABB77` 包。Make 本轮跟的是这条已有文本约定，**没有**新发明 DC/MC 长串。把 GameSvr 日志改成二进制包是独立协议项（§1.4），本轮不碰发送层。
