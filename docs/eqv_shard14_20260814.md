## 4. MISSING 明细：MINE-49（骑乘态攻击门，共享 HIT 派发器）

**证据**：HIT 族派发器 `sub_6D9EAF` 在调用 ClientHitXY(`0x6EC078`) 前：
```
0x6D9EBC  call 0x6BBEB8
0x6D9EC1  test al,al
0x6D9EC3  jne  0x6DBC2C      ; 放弃整个 case
```
`sub_6BBEB8`：`HasState(0x33=51) || HasState(0x34=52)` 命中即返回 1。经查 `TPlayObject.NativeRun3Horse.cs:7-8`：state 51=`NativeHorseMountedState`、52=`NativeHorseBlockedState`。即**骑乘/坐骑受阻时禁止一切 HIT 族动作（含挖矿 CM_HEAVYHIT）**。

**C# 现状**：出队派发 `TPlayObject.Message.cs:1645-1676`（CM_HIT..CM_3037）与 `ClientHitXY` 开头（`m_boCanHit`/死亡麻痹/测速/区域门）**均无** state 51/52 门；上马 `SetNativeActiveState(51)` 亦不置 `m_boCanHit=false`。故骑乘玩家仍可攻击/挖矿——**MISSING**。

**为何只报不改**：该门位于**共享 HIT 派发器**，作用于全部 hit ident（TSV blast_radius=COMBAT），且 state 51/52 归属已充分实现的坐骑/移动子系统（`NativeRun3Horse`/`NativeHorsePartner`/`NativeHorseDismount` 等）。属跨挖矿域的战斗/坐骑热点，按铁律「热点只报不改」。

**建议的外科修法（交战斗/坐骑域负责人）**：在 `ClientHitXY` 首句 `m_boCanHit` 之后或 Message.cs:1645 case 顶部加：
```csharp
if (HasNativeActiveState(0x33) || HasNativeActiveState(0x34))
    return result;   // native sub_6BBEB8: 骑乘(51)/坐骑受阻(52) 禁 HIT 族
```
