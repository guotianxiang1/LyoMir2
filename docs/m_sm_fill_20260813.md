## 2. 本轮落地：SM 3554（`srv 50,911`，提交 `595d6057`）

### 2.1 帧（本轮亲自反汇编，非抄报告）

### 2.2 三条交叉证据

1. **链表同源**：3555 的取节点函数 `0x773B98` 在 `0x773BBA mov eax,[esi+0xDC]` 走的是**同一个 `[self+0xDC]`**，
   即 `m_TimedAbilityHead`。所以 3554 遍历的正是 C# 已有的计时能力链表。
2. **触发唯一**：`sub_6E99B8` 只有 1 个 `E8` 调用者 `0x6E9AAE`，在登录突发 `sub_6E9A98` 内，
   顺序为 `3324(0x7468B4) → 1264(0x6F0A50) → 3554(0x6E99B8) → 3556/4367(0x74839C)`；
   四者 srv 全 = 50,911 = `SM_LOGON(50)` 的登录次数（B §4.2），即**每次登录发一次**。
3. **空表仍发**：`je 0x6E9A4C` 只跳过打包不跳过发送，`ebx=0`，Len=0 —— 与 SM 4612 空表仍发同形。

### 2.4 触发位置的诚实说明

登录突发 `sub_6E9A98` 经 VMT 调用（dword 引用在 `0x62F190`/`0x6ACACC` 两个 VMT 槽），
其在登录流程内的**精确相对位置未做字节钉定**。但「每次登录发一次」是硬契约（srv=50,911 精确等于登录数），
故置于 C# 登录包块中、与其它登录列表包同组即可满足契约；包间顺序非协议约束（客户端逐包独立处理）。
英雄（`HeroObject` 非 `TPlayObject`）不继承此登录路径，与原生 TPlayer 槽一致。
