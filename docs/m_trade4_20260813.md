## 1. `DealValidationFailureSemanticsCheck` / TCFP-22

### 1.1 审计在钉什么

`AuditTools/DealValidationFailureSemanticsCheck/Program.cs` 从 `if (m_DealCreat.m_boDealOK)` 起截 **2000 字符**，grep `` `bo11 &&` ``，要求 ≥ 3。全量基线：`found 0`。

## 2. `MovementCollisionCheck`：死亡与在线人数

### 2.1 审计在钉什么

`Equal(0, HumCount, "player death changed legacy active-player accounting")`：期望死亡后 HumCount 从 1 变成 0。实测 **got 1**（死亡后没减）。

### 2.2 原生死亡路径（玩家）

TPlayer VMT `0x6AC8C8+0x84` = `0x6C07A0`：

```
0x6C07A0  TPlayer.Die
0x6C07D8  E8 8B 0B 08 00        call 0x741368                 ; THumanKind.Die
0x74138A  E8 8D 4F 02 00        call 0x76631C                 ; TCreature.Die
```

`TCreature.Die` 全文很短：

```
0x766323  C6 43 74 01           mov byte [ebx+0x74], 1        ; m_boDeath
0x766327  E8 14 20 CA FF        call 0x408340                 ; GetTickCount
0x76632C  89 83 30 03 00 00     mov [ebx+0x330], eax          ; m_dwDeathTick
0x766351  FF 51 08              call [map.vmt+8]              ; 地图通知，见下
```

**不写 `[+0x73]`（ghost）**。ghost 唯一写入点仍是 MakeGhost `0x7680EF C6 43 73 01`。

地图类指针 `[0x5FB218]=0x5FB264`（自指针校验通过），`VMT+8=0x5FD4D4`：

```
0x5FD4D4  eax=map, edx=dying
0x5FD4E1  E8 7E CA 17 00        call 0x779F64                 ; 父方法
0x5FD4EA  80 BB 78 01 00 00 00  cmp byte [ebx+0x178], 0       ; race==0 玩家支
          … ghost 门 + [map+0xA4] 通知，不碰 HumCount
0x5FD515  3C 32                 cmp al, 0x32
0x5FD517  72 17                 jb  ret                       ; race<50 直接返回
          … 否则可能 dec [obj+0x4B4]+0x2C（刷怪计数，玩家走不到）
```

HumCount 在 `map+0xD8`，**只**在 AddToMap / DeleteFromMap 里对 race==0 加减：

```
VMT+4 0x5FD534  0x5FD559  FF 83 D8 00 00 00  inc dword [ebx+0xD8]   ; Add，race==0
VMT+0 0x5FD574  0x5FD592  FF 8B D8 00 00 00  dec dword [ebx+0xD8]   ; Del，race==0
```

`RC_PLAYOBJECT = 0`，与 `+0x178==0` 对齐。

**结论：死亡不等于下线。尸体仍占格，HumCount 不变。复活也不碰 HumCount。换图才走 DeleteFromMap/AddToMap。**

### 2.3 C# 差在哪

`TBaseObject.Die` 在发 `RM_DEATH` 之前：

```
if (m_Master == null && !m_boDelFormMaped)
{
    m_PEnvir.DelObjectCount(this);   // HumCount--
    m_boDelFormMaped = true;         // 之后 DeleteFromMap 跳过第二次 --
}
```

这是把死亡当成「从地图人数里注销」，和 ghost/下线混用。审计期望 0 是在钉这个错误行为。测试 got 1，是因为 `Die()` 第三段 try 里 `AddGameDataLog` 等在 fixture 里抛了，`DelObjectCount` 没跑到——**碰巧露出了原版值**。

`ReAlive` 只清 `m_boDeath`，不 `AddObject`。若 Die 减了数，复活后 HumCount 永远少 1。

### 2.4 修复

- 产品：删掉 Die 里那两行。死亡只置 `m_boDeath`、广播 `RM_DEATH`。
- 审计：死亡后 / 复活后 HumCount 期望 **1**；尸体换图期望源 0、目标 **1**（正常 Delete/Add）。

动态房占用（格子上还有人）本来就没减，保持期望 1。那条是对的。

## 3. TRADE-61 GM 旁路（分析，未落地）

### 3.1 完整语义

`sub_6C417C` ClientAddDealItem，对端非空之后：

```
0x6C4197  83 BB AC 0B 00 00 00     cmp dword [ebx+0xBAC], 0     ; partner nil → 出口
0x6C41AD  80 BB 75 06 00 00 04     cmp byte [ebx+0x675], 4      ; 自己权限
0x6C41B4  73 13                    jae 0x6C41C9                 ; >= 4 → al:=1
0x6C41B6  8B 83 AC 0B 00 00        mov eax, [ebx+0xBAC]
0x6C41BC  80 B8 75 06 00 00 04     cmp byte [eax+0x675], 4      ; 对端权限
0x6C41C3  73 04                    jae 0x6C41C9                 ; >= 4 → al:=1
0x6C41C5  33 C0                    xor eax, eax                 ; 双方都 < 4 → al:=0
0x6C41C7  EB 02                    jmp 0x6C41CB
0x6C41C9  B0 01                    mov al, 1
0x6C41CB  88 45 EE                 mov [ebp-0x12], al

0x6C421D  80 7D EE 00              cmp byte [ebp-0x12], 0
0x6C4221  75 1B                    jne 0x6C423E                 ; 旁路 → 跳过 0x78389C
0x6C4229  BA 02 00 00 00           mov edx, 2                   ; mode 2 = 交易
0x6C4230  E8 67 F6 0B 00           call 0x78389C                 ; 绑定/禁交易判定
0x6C4238  83 7D F0 00 / 7F 56      cmp [ebp-0x10],0 / jg 拒绝
```

**「任一方」是真的双向 OR**：自己 `>= 4` **或** 对端 `>= 4`。`jae` 无符号，权限字节 4..255 全开。对端指针在 0x6C4197 已判过非空，第二读不会空解引用。

`[obj+0x675]` = C# `m_btPermission`。同一字节在 `AddItemToBag`：`0x6B73A3 cmp byte [player+0x675], 3 / ja` 跳过盖印，即 **> 3 ≡ >= 4**，与这道旁路阈值一致。`MaxStampedGmLevel = 3`。

### 3.2 若照抄会带来什么

这是交易链上**唯一**拦绑定物 / `Reserved02` 禁交易位的门。开口挂在**对端**权限上：

| 自己 | 对端 | 绑定物能否进交易格 |
|---|---|---|
| < 4 | < 4 | 否（走 0x78389C） |
| ≥ 4 | 任意 | 是 |
| 任意 | ≥ 4 | **是** —— 普通玩家把绑定物交给 GM |

风险：

1. GM 与玩家交易时，**玩家侧**也能放绑定物。这不是「GM 自己作弊」，是对端权限给整笔交易解绑。
2. `m_btPermission` 若被脚本/命令/存档写到 ≥ 4，整条绑定门作废。
3. 成交走 `AddItemToBag(..., stampEnable: true)`，对方权限 ≥ 4 时盖印被跳过（同一 `>= 4`），绑定位一旦在放物时被旁路，成交后不会补盖。
4. 本镜像没有第二道成交时绑定复查。放物过了就是过了。

### 3.3 建议（交主控）

- **默认 fail-closed：不落地。** 缺这道门 = 比原版紧（GM 也不能用交易搬绑定物），不丢物、不刷物。
- 若要 1:1：必须同时钉死 `m_btPermission` 的赋值域（登录、GM 命令、脚本 `gmlevel`）与原版 `[+0x675]` 一致，并在审计里钉「双方都 < 4 时 0x78389C 必跑」。
- 不要做成「只有自己 ≥ 4 才旁路」——那不是原版。要么整段照抄双向 OR，要么整段不抄。

C# `ClientAddDealItem` 当前无此旁路。**MISSING，本轮不改。**

## 4. BLOCKED-1：`sub_6D7CB0` 与 `SendDefMessage` 对位

### 4.1 形参对位（已钉死）

`TPlayer VMT+0x250 = 0x6D7CB0`，`ret 0x10` = 四个栈 DWORD。

```
0x6D7CB9  89 4D F8              mov [ebp-8], ecx              ; nRecog
0x6D7CBC  66 89 55 FE           mov [ebp-2], dx               ; wIdent
0x6D7CC2  8B 75 08              mov esi, [ebp+8]              ; sMsg（后测 0x4057D0 取长串长度）
0x6D7D21  8B 45 F8 / 89 45 EC   Recog → 12 字节头 +0
0x6D7D27  66 8B 45 FE / 89 45 F0 Ident → +4
0x6D7D2F  66 8B 45 14 / 89 45 F2 [ebp+0x14] → Param +6
0x6D7D37  66 8B 45 10 / 89 45 F4 [ebp+0x10] → Tag   +8
0x6D7D3F  66 8B 45 0C / 89 45 F6 [ebp+0xC]  → Series +0xA
0x6D7D63  C2 10 00              ret 16
```

Delphi register：`eax=Self, edx=wIdent, ecx=nRecog`，栈从左到右先压 Param。

| 原生 | 槽 | C# `SendDefMessage` |
|---|---|---|
| `edx` | wIdent | 第 1 参 `wIdent` |
| `ecx` | nRecog | 第 2 参 `nRecog` |
| `[ebp+0x14]` 先压 | Param | 第 3 参 `nParam` |
| `[ebp+0x10]` | Tag | 第 4 参 `nTag` |
| `[ebp+0xC]` | Series | 第 5 参 `nSeries` |
| `[ebp+8]` 后压 | sMsg | 第 6 参 `sMsg` |

与 `MakeDefaultMsg(ident, Recog, param, tag, series)` 同序。**对位 FAITHFUL。**

### 4.2 仓库 FULL/FAIL 把容器号放在哪

`sub_6C2A34` 栈参 = CM Series+1（分发 `0x6D91BE 66 8B 40 0A` / `0x6D91C2 66 83 E8 03 jae` 只放行 Series∈{0,1,2} / `0x6D91D3 40 inc` / `push`）。

函数内 `[ebp-0xa]`：

```
0x6C2A65  66 C7 45 F6 00 00     mov word [ebp-0xa], 0         ; 默认普通仓
0x6C2A6B  8B 45 08 / 83 E8 02   sub eax, 2
0x6C2A71  74 05                 je  → Series 1 → 容器 1（账号仓 +0x6D4）
0x6C2A73  48 / 74 1D            dec / je → Series 2 → 容器 2（药仓 +0x6D8）
```

FULL：

```
0x6C2CCA  6A 00                 push 0                       ; sMsg
0x6C2CCC  6A 00                 push 0                       ; Tag
0x6C2CCE  66 8B 45 F6 / 50      push word [ebp-0xa]           ; Series = 容器号
0x6C2CD3  6A 00                 push 0                       ; Param
0x6C2CD5  33 C9                 xor ecx, ecx                 ; Recog = 0
0x6C2CD7  66 BA BE 02           mov dx, 0x2BE                ; SM_STORAGE_FULL = 702
0x6C2CDF  FF 96 50 02 00 00     call [vmt+0x250]
```

FAIL 同形，`dx=0x2BF`（SM_STORAGE_FAIL=703）。成功包 `0x6C2C3D` 同样把 `[ebp-0xa]` 压进 Series。

因此：`SendDefMessage(ident, 0, 0, 0, container, "")`。
