## 1. 真实线上 ident 全集的取法

### 1.1 判据本身要先修正

F-2 给的判据是「是否出现在真正走发送槽 `[+0x250]`/`[+0x254]` 的函数里」。
**照字面执行会误杀。** 只扫这两个槽得到 474 个 ident，与生产计数器对账只覆盖
**168/198 = 84.8%**，漏掉的里面有 `1230`（572 万次）、`801`（50 万次）、`807`（56 万次）。

漏的原因是发送路径不止那两个字段槽：

| 路径 | 形态 | 例证 |
|---|---|---|
| `[obj+0x250]` | 字段调用，末尾 `sMsg` | 554 个点 |
| `[obj+0x254]` | 字段调用，末尾 `(Buf, Len)` | 182 个点 |
| `[vmt+0x0E0]` | **虚方法**，先 `mov reg,[obj]` 再 call | 81 个点，`1230` 的 6 个下发点全在这里 |
| CX 型包装器 | `mov cx,ident` → 直接 `call`，包装器内部再进 `[+0x254]` | `0x6BCE54`，`801`/`807` 走它 |

`1230` 的六个点（`0x690DEE / 0x690F62 / 0x691040 / 0x6918B6 / 0x770E39 / 0x770E5A`）
与 REPLICATION_RULES §1.4「1230 在原生镜像有 6 个发出点」完全吻合，反过来证明
`[+0xE0]` 必须计入。

`0x6BCE54` 是包装器不是终点，它把 `cx` 存进 `[ebp-2]` 再取回来发：

```
0x6BCE54  55                    push ebp
0x6BCE5D  66 89 4D FE           mov  word ptr [ebp-2], cx     ; ident 入栈槽
...
0x6BCECC  6A 20                 push 0x20                     ; Len = 32
0x6BCED0  66 8B 55 FE           mov  dx, word ptr [ebp-2]     ; 取回
0x6BCED8  FF 93 54 02 00 00     call dword ptr [ebx+0x254]
```

调用侧（`801`）：

```
0x6B59F5  8B 53 24              mov  edx,[ebx+0x24]
0x6B59F8  66 B9 21 03           mov  cx, 0x321                ; ident 801
0x6B59FF  E8 50 74 00 00        call 0x6BCE54
```

### 1.2 最终算法

`staging/_sm1_work/s08_final.py`：

1. 按字节枚举三类槽的全部 **817** 个调用点（`FF /2 disp32`，8 个基址寄存器）。
2. 每个点做**锚定反向反汇编**：从 `anchor-200` 到 `anchor-4` 逐个起点试解，取能恰好在
   anchor 处对齐且最长的那条链（736/736 成功，比线性扫描可靠得多）。
3. 沿链回溯 `edx` 的最后一次完整写入，取立即数。
4. `edx` 是动态值的点，对所属函数做**前向符号模拟**，判断 ident 来自哪个入参寄存器；
   该函数即包装器。再到包装器自己的调用点上取立即数，迭代到不动点。
5. **VCL 过滤**：`[vmt+0xE0]` 是很低的 VMT 下标，每个 Delphi 类都有，窗体类会假命中。
   丢掉全部下发点都 `< 0x600000` 的值——**恰好只丢掉 1 个值：`0`**。

结果 **503 个 ident**。与生产计数器对账覆盖 **180/198 = 90.9%**。

> 「只丢掉 0 这一个」是独立复现了 `w/m-sm-a` §1.1 的同一处修正
> （他们查 VMT `0x795590 = TSearchLogForm` 得到同一结论）。两条互不相同的路径
> 收敛到同一个假阳性，这条可以当定论。

### 1.3 全集是下界，不是闭集——必须写清楚

剩下 18 个 ident 在生产流量里出现、但静态解不出来：

`32(568万) 34(1825万) 3290 4003 4004 4010 4012 4013 4014 4017 4018 4031 4039 4040 4041 4042 4332 4497`

两个不同的原因，都必须记住：

**(1) ident 从队列记录里转发出去，不是立即数。** 分发臂写的是 `mov edx,[eax]` / `mov edx,esi`，
静态解不出。`32`/`34` 就是这样（`w/m-sm-a` §1.2 反出了合流臂
`0x6B49D3 66 B8 22 00 mov ax,0x22` / `0x6B49D9 66 B8 20 00 mov ax,0x20` → `0x6B49EF mov ecx,eax`
→ `call 0x6BCE54`，经 `ax` 中转，我的扫描器同样看不见）。

**(2) 有些 ident 根本不是 M2Server 发的。** `4003` 和 `4010` 在整个镜像里
**五种立即数形态（`mov dx/cx,imm16`、`mov edx/ecx,imm32`、`push imm32`）全部 0 命中**，
却分别有 38,828 / 81,794 次流量。

> **给所有用这两个计数器的代理：`srv_AppearTimes.ini` 是 GameGate 的计数器，
> 统计的是网关看见的包，不等于 M2Server 的输出。** 40xx 波段里 `4012`/`4039`
> 在 `client_` 和 `srv_` 两侧计数**完全相同**（12797 / 9007），是网关级别的透传或
> 网关自产。拿它反推「原生 M2Server 一定发过这个 ident」会错。
> 反过来用（出现过就别删）永远是安全的，本轮只这么用。

**因此 503 这个集合只用于「确认是」，绝不单独用于「确认不是」。**
判某个值不是 ident，必须同时满足：不在 503 集合、不在流量计数器、
且该值的全部立即数装载点都走不到发送槽。

### 2.2 【严重】F-2 的判据字面执行会误杀 1230 / 801 / 807

**F-2 的判据应补上 `[vmt+0xE0]` 与包装器两跳。**

### 2.3 `0x784A10` 长得像发送函数，其实是一张 word 键值表的更新

`0x760B52 66 BA 20 00 mov dx,0x20` / `0x762009 66 BA 22 00 mov dx,0x22` 后面紧跟
`call 0x784A10`，形状和 `mov dx,ident / call 包装器` 一模一样。但它不是：

```
0x784A16  66 89 4D FE           mov  word ptr [ebp-2], cx
0x784A1A  8B F2                 mov  esi, edx                  ; key
0x784A30  8B 4B 10              mov  ecx,[ebx+0x10]
0x784A33  66 3B 34 81           cmp  si, word ptr [ecx+eax*4]  ; 按 key 线性查找
0x784A37  75 0E                 jne  0x784A47
0x784A40  66 89 4C 82 02        mov  word ptr [edx+eax*4+2], cx ; 命中 -> 改 value
...
0x784A76  66 89 74 82 FC        mov  word ptr [edx+eax*4-4], si ; 未命中 -> 追加 (key,value)
0x784A8A  66 89 4C 82 FE        mov  word ptr [edx+eax*4-2], cx
```

即 `[obj+0x10]` 是一张 4 字节一项的 `(word key, word value)` 表，这个函数是
「有则改、无则加」。**`edx` 是 key 不是 ident，全函数没有任何发送槽调用。**
`0x768BE0` 同理（它把 `[obj+0x106]` / `[obj+0x115]` 两个 ShortString 转成长串后
调全局对象 `[0x7D5ECC]`，也没有发送槽）。

记这一条是因为：**只按「`mov dx,imm` 后面跟 call」认发送点会把这两个误收进来。**

### 2.4 `0x5F6F9C` / `0x5F709C` 是另一套传输，不是客户端下行

`3290`、`4497` 走的是它们，包头魔数 `0x33AABB77`，结构 0x1C 字节，
然后对 `[esi+ebx*4+0x30C]` 的 **32 个槽位**逐个 `call 0x5F6A68`：

```
0x5F6FD0  C7 45 E0 77 BB AA 33  mov  dword ptr [ebp-0x20], 0x33AABB77
0x5F6FD7  66 C7 45 EC 12 00     mov  word  ptr [ebp-0x14], 0x12
0x5F6FE1  66 89 7D F4           mov  word  ptr [ebp-0x0C], di    ; ident 落在偏移 0x14
0x5F6FF2  8B 84 9E 0C 03 00 00  mov  eax,[esi+ebx*4+0x30C]       ; ebx = 1..0x20
0x5F7007  E8 5C FA FF FF        call 0x5F6A68
```

这是 32 路广播（服务器组 / 网关组），与 `TDefaultMessage` 不是同一张表。
本轮**没有**把它的 ident 并进 503 集合，`3290`/`4497` 因此留在「解不出」那 18 个里。
要不要并入需要先定这张表的语义，属 §6 BLOCKED-3。

## 3. 类 (a)：内部队列标签冒充 SM_ —— 1 项，已修

### `SM_LINGFU_CHANGED = 10054` → `RM_LINGFU_CHANGED`（提交 `d39c87a3`）

判定方式：把 C# 里全部 162 个 `RM_*` 取值按「间隔 > 300 断带」聚成 8 个带
（`8020-8106 / 9041-9043 / 10001-10625 / 11001-11010 / 12309 / 15000-15323 / 25008 / 50003`），
再找落在带内、且既不在 503 集合也不在流量里的 `SM_*`。**全库只有这一个。**

它当时就声明在 RM 块中间：

```
public const int RM_DAYCHANGING = 10053;
public const int SM_LINGFU_CHANGED = 10054;   // <- 前缀错了
public const int RM_USERMOVE = 10056;
```

**内部 tag = 10054（`0x2746`）。** 全镜像只有一处立即数装载，而且是入队不是发送：

```
0x6B99EB  6A 00              push 0
0x6B99ED  6A 00              push 0
0x6B99EF  6A 00              push 0
0x6B99F1  6A 00              push 0
0x6B99F3  66 B9 46 27        mov  cx, 0x2746     ; tag 10054
0x6B99F7  8B D0              mov  edx, eax
0x6B99F9  E8 6A C4 0A 00     call 0x765E68       ; F-2 点名的那个入队函数
0x6B99FE  5D                 pop  ebp
0x6B99FF  C3                 ret
```

`sub_765E68` 经 `0x764D68` 分配记录后填字段，全函数无
`[+0x250]`/`[+0x254]` 调用——与 F-2 定点坐标那例是同一个函数、同一个形状。

**线上 ident = 1202（`0x4B2`）。** 分发器把 tag 减去 10000 后查跳表：

```
0x6B3EF8  05 F0 D8 FF FF        add  eax, 0xFFFFD8F0          ; -10000
0x6B3EFD  3D 86 00 00 00        cmp  eax, 0x86
0x6B3F02  0F 87 39 23 00 00     ja   0x6B6241                 ; default = 静默丢弃
0x6B3F08  FF 24 85 0F 3F 6B 00  jmp  dword ptr [eax*4+0x6B3F0F]
```

表基址 `0x6B3F0F`，第 54 项 = `0x6B4DED`。该臂取六个 dword 拼成 24 字节体后：

```
0x6B4DED  8B 45 FC / 8B 80 D8 0B 00 00   [ebp-0x38] = [Self+0xBD8]
0x6B4DF9  8B 45 FC / 8B 80 60 07 00 00   [ebp-0x34] = [Self+0x760]
0x6B4E05  8B 45 FC / 8B 80 F0 0B 00 00   [ebp-0x30] = [Self+0xBF0]
0x6B4E11  ... [Self+0x1824] 的 +8 / +0x24 / +0x28 -> [ebp-0x2C/-0x28/-0x24]
0x6B4E2C  6A 00                push 0            ; Param
0x6B4E2E  6A 00                push 0            ; Tag
0x6B4E30  6A 00                push 0            ; Series
0x6B4E32  8D 45 C8 / 50        push &[ebp-0x38]  ; Buf
0x6B4E36  6A 18                push 0x18         ; Len = 24
0x6B4E38  33 C9                xor  ecx, ecx     ; Recog = 0
0x6B4E3A  66 BA B2 04          mov  dx, 0x4B2    ; <<<< 线上 ident 1202
0x6B4E3E  8B 45 FC / 8B 18     mov  eax,[ebp-4] / mov ebx,[eax]
                               call dword ptr [ebx+0x254]
```

流量交叉验证：`1202 = 518428`（有），`10054`（无）。

**C# 侧原本行为是对的**，只有名字错：`RefreshNativeLingFu()` 用 `SendMsg` 入队，
处理臂 `case ...: SendNativeCapitalInfo()` 发的是 `SM_GETDIAMNUM_EXT = 1202`，
24 字节体、`Recog/Param/Tag/Series` 全 0，与原生逐字段一致。
所以本项**只改名、不改线**，44 处引用横跨 21 个文件全部同步。

改它的理由不是洁癖：`LingFuCompatCheck/Program.cs` 里早就有一条
`Reject(..., "SendDefMessage(Grobal2.SM_LINGFU_CHANGED")`——
说明已经有人担心过有人会把它直接发出去。这正是 F-2 那次事故的成因。
