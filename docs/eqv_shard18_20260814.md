### 本波外科修复（提交 `e1b6dab7`）

`Maps.cs` SAFE 臂原用 `.Equals("SAFE")` 精确匹配、且把 NOTHROUGH 当独立 token（发明）。
二进制证实 SAFE 是**长度 4 前缀比较**且 NOTHROUGH 是 `SAFE(NOTHROUGH)` 的括号参数：

```
0x776081 mov ecx,4 / edx="SAFE"(0x776B20) / call 0x4C6E94   ; 前缀,大小写不敏感
0x77608A mov byte [ebx+0x5C],1                               ; boSAFE
0x7760A3 call 0x4C6964                                       ; 取 "(...)" 参数
0x7760AB edx="NOTHROUGH"(0x776B48) / 0x7760B0 call 0x40591C  ; 全等,大小写敏感(无 UpCase)
0x7760B7 mov byte [ebx+0x84],1  /  0x7760C3 mov byte [ebx+0x84],0
```

修复：SAFE 改 `CompareLStr` 前缀匹配 + 解析 `(NOTHROUGH)`→`boNOTHROUGH`（`Ordinal` 大小写敏感）；
移除 `TryApplySceneFlag` 里发明的独立 NOTHROUGH 臂。唯一可观测修正是 `SAFE(...)` 现能正确置
`boSAFE`（`boNOTHROUGH` 目前无消费者）。`dotnet build GameSvr`：0 errors。

## 三、报告不修的大缺口（热点/大缺口只报不改）

### 缺口① @TempSetMapParam 运行时切换仅移植 PICKUP（影响 MFLG-17/18/20-A/23 的 GM 侧）

原生 Parser A（`sub_774D24`）能对约 50 个旗标做 set/clear 运行时切换，返 1(成功)；仅对
CHECKQUEST 与未识别 token 返 0x64。C# `TempSetMapParamCommand.ApplyPickupAttribute` **只认
"pickup"**，其余一律返 0x64=不支持（有 `NativeTempSetMapParamPickupCheck` 审计工具锁定此范围）。

- 后果分歧：`@TempSetMapParam <map> SAFE 1` 原生会置 SAFE 并报"增加地图属性=SAFE，操作成功"；
  C# 报"该GM命令目前不支持此地图属性=SAFE"。
- 消息与返回约定本身**忠实**（0x62DB74 等逐串对齐），差异纯在**覆盖旗标集**。
- 不修理由：需复刻约 50 个 toggle 臂（含 NOC2C 计算臂、数值 toggle-off 写 0/0xffff、CHECKQUEST
  0x64、失败路径 0x6299F5 的分支）——属大缺口；且前波已刻意缩窄。建议按需另起专项移植。
