## 1. 数据结构全貌

### 1.1 调用约定

`sub_1006CF10(arg)` → `ecx = player`、`edx = player+0x508`（`TList` 背包）、
`push [list+8]`（`FCount`）→ `sub_1006B020`。

```
1006CF49  8B 98 08 05 00 00  mov ebx,[eax+0x508]   ; m_ItemList (Delphi TList)
1006CF52  8B 53 08           mov edx,[ebx+8]       ; TList.FCount
1006CF64  E8 B7 E0 FF FF     call 0x1006B020
```

### 1.2 物品记录（内存态，`item+0x00` 起）

`item+0x00..0x1F` 是运行期前缀（**不落盘**），`item+0x20` 起是 208 字节持久化 blob
（M2Server `0x6B170F lea esi,[eax+0x20] / 0x6B1712 mov ecx,0x34 / rep movsd`）。

| 偏移 | 含义 | 证据 |
|---|---|---|
| `+0x14` | StdMode（`==7` 为可叠加） | M2Server `0x6C1F31 80 7B 14 07` / `0x61E9A8` |
| `+0x1C` | → StdItem 对象；`+4` 是 NUL 结尾的物品名 | `0x1006B3AF 8B 50 1C` / `0x1006B3B2 8D 52 04`；插件共 8 处同一惯用法 |
| `+0x26` | `Dura`（可叠加物品的堆叠数） | `0x1006BB2F 66 8B 58 26`；M2Server `0x61E9AE 0F B7 40 26` 与请求数量比较 |
| `+0x2A..0x2F` | 极品 6 位 | `0x1006C10A..0x1006C137` |
| `+0x78..0x8B` | 元素 17 位 | `0x1006C39D..0x1006C456` |

**极品槽 → 偏移（非顺序）**：
jp1=`+0x2B`、jp2=`+0x2A`、jp3=`+0x2F`、jp4=`+0x2E`、jp5=`+0x2D`、jp6=`+0x2C`。

**元素槽 → 偏移（非顺序，且 1 号是 dword）**：

| 槽 | 偏移 | 宽度 |
|---|---|---|
| 1 | `+0x7C` | **dword**（`0x1006C39D 8B 46 7C`） |
| 2 / 3 / 4 / 5 | `+0x7B` / `+0x7A` / `+0x79` / `+0x78` | byte（地址递减） |
| 6..17 | `+0x80`..`+0x8B` | byte（地址递增） |

这与仓库里 `SystemModule/Packet/YanshenNativeItemLayout.cs` 从**另一处**插件代码
（`0x10075C8D` / `0x10075CF9` / `0x10075D48`）独立解出的布局逐字段一致 —— 两条独立路径收敛。

### 1.3 配置结构（`recycle.json`）

三个根键：`可叠材料`、`物品种类`（两者都是 `物品名 → 类型名`）、`回收类型`（`类型名 → 规则`）。

规则字段（**全部可省略**，缺省语义各不相同）：

| 键 | 形状 | 语义 | 缺省 |
|---|---|---|---|
| `总开关` | `{v1,v2,关闭值}` | `GetV(v1,v2) == 关闭值` ⇒ 该类型停收 | 关闭值预置 **-2**（`0x1006B2F4 C7 45 84 FE FF FF FF`），`< -1` 整道门失效 |
| `回收倍率` | `{v1,v2}` | `GetV(v1,v2)` 为百分数，200 = 2 倍 | `<= 0` ⇒ 1 倍 |
| `极品开关` | int（变量组号） | `GetV(组号, 1..6)` 为每位阈值 | 缺省不过滤 |
| `元素开关` | int（变量组号） | `GetV(组号, 1..17)` 为每位阈值 | 缺省不过滤 |
| `元宝`/`金币`/`灵符`/`经验` | int | 单件单价 | 0 |
| `其他` | `{v1,v2,值}` | 每件 `SetV(v1,v2, max(GetV,0)+值*倍率*件数)` | 不写 |

`v1` = 变量组、`v2` = 变量下标：Delphi `GetV(EAX=Self, EDX=nGroup, ECX=nIndex)`，
插件在 `0x1006BD1A mov edx,[ebp-0x98]`（v1）/ `0x1006BD20 mov ecx,[ebp-0x9C]`（v2）。

**V 银行键 = `组*1000 + 下标`**（`0x6E42CC 69 C2 E8 03 00 00 imul eax,edx,0x3E8 / 03 C1 add eax,ecx`），
稀疏有序数组 + 二分查找，**未命中返回 -1**（`0x6E427A C7 45 FC FF FF FF FF`）。
这一条决定了整套开关的默认方向，见 §5。

## 2. 判定链（逐分支字节证据）

主循环从 **背包末尾向前**：

```
1006B282  8B 55 08   mov edx,[ebp+8]     ; FCount（仅首次）
1006B285  4A         dec edx             ; ← 循环头
1006B28E  0F 88 ...  js  0x1006CE42      ; edx < 0 ⇒ 收尾
...
1006CE37  8B 95 FC FE FF FF  mov edx,[ebp-0x104]
1006CE3D  E9 43 E4 FF FF     jmp 0x1006B285
```

倒序是删除安全的前提：`TList.Delete(idx)` 只搬动 idx 之后的元素。

| # | 分支 | 字节 | 结果 |
|---|---|---|---|
| 1 | 物品名指针为空 | `0x1006B3C3 85 D2` / `0x1006B3C5 je 0x1006CE37` | 跳过 |
| 2 | 根键 `可叠材料` 不存在 | `0x1006B3E1 call 0x100E1210` / `0x1006B3E8 je 0x1006BD39` | 转 物品种类 分支 |
| 3 | 物品不在 `可叠材料` | `0x1006B408 call 0x100E1240` / `0x1006B40F je 0x1006BD39` | 转 物品种类 分支 |
| 4 | **可叠材料** 的类型名不在 `回收类型` | `0x1006B462 80 78 08 00 cmp byte [eax+8],0` / `0x1006B466 75 0C jne` / `0x1006B46F jmp 0x1006CE26` | **跳过，不删** |
| 5 | 物品不在 `物品种类` | `0x1006BD53 call 0x100E1240` / `0x1006BD5A je 0x1006CE2B` | **跳过，不删** |
| 6 | **物品种类** 的类型名不在 `回收类型` | `0x1006BDA8 call 0x100E1240` / `0x1006BDAF je 0x1006CE1F` | **跳过，不删** |
| 7 | 总开关命中关闭值 | 见下 | 跳过 |
| 8 | 极品阈值命中 | `0x1006C2F6 C7 45 9C 64 …` / `0x1006C2FD jmp 0x1006CE1F`（共 6 段） | 跳过 |
| 9 | 元素阈值命中 | `0x1006C6AB` / `0x1006C6B2 jmp 0x1006CE1F`（共 17 段） | 跳过 |
| 10 | 五路产出全 `<= 0` | `0x1006BB3B..0x1006BB57`（叠加）/ `0x1006CC6B..0x1006CC82`（种类） | **跳过，不删** |
| 11 | 删除前物品指针已变 | `0x1006BB7F 3B C6` / `0x1006BB81 jne 0x1006BBC8` | 不删 |

**四号分支就是生产里 `玛法金骨` / `丹书铁卷` → `类型2` 的那条。**
jsoncpp 的非 const `operator[]` 对缺失键会**自动插入一个 `nullValue` 并返回引用**，
所以 `[eax+8] == 0` 正是「这个类型名不存在」，落到跳过臂。**整条链在不匹配时全部 fail-safe。**

### 2.1 优先级

`可叠材料` **先判**（`0x1006B3E1`），命中就走完整条堆叠分支，**绝不回落**到 `物品种类`。
同名项以 `可叠材料` 为准。

### 2.2 总开关：两条分支的前置条件不一样

可叠材料侧（`0x1006B783`）：

```
1006B783  83 7D 84 FF  cmp dword [ebp-0x7C], -1   ; 关闭值
1006B787  7C 23        jl  0x1006B7AC             ; < -1 ⇒ 整道门失效
1006B78D  8B 95 7C FF FF FF  mov edx,[ebp-0x84]   ; v1 → nGroup
1006B793  8B 8D 78 FF FF FF  mov ecx,[ebp-0x88]   ; v2 → nIndex
1006B799  FF 15 58 BC 31 10  call [0x1031BC58]    ; GetV (0x6DF1E4)
1006B79F  3B 45 84     cmp eax,[ebp-0x7C]
1006B7A2  75 07        jne 0x1006B7AB             ; 不等 ⇒ 放行
1006B7A4  C7 45 9C 64 00 00 00  mov [ebp-0x64],0x64   ; 拦下
```

物品种类侧（`0x1006C0BE`）**多两条**：

```
1006C0C4  83 BD 7C FF FF FF 00  cmp dword [ebp-0x84],0   ; v1
1006C0CB  7E 2C                 jle 0x1006C0F9           ; v1 <= 0 ⇒ 门失效
1006C0CD  83 BD 78 FF FF FF 00  cmp dword [ebp-0x88],0   ; v2
1006C0D4  7E 23                 jle 0x1006C0F9
```

四个子键（`总开关` / `v1` / `v2` / `关闭值`）**缺任何一个**，整段 `总开关` 都不解析
（`0x1006B4A1` / `0x1006B4E2` / `0x1006B523` / `0x1006B564` 四个 `je 0x1006B633`），
关闭值停在预置的 -2，门失效。

### 2.3 极品 / 元素：方向是 `>=`，不是作者文档写的 `>`

先有「全零就整段跳过」的前置：极品 `0x1006C142..0x1006C176`（6 个 `cmp …,0`，全 0 则
`je 0x1006C398`）；元素 `0x1006C45E..0x1006C501`（17 个，全 0 则 `je 0x1006C882`）。

阈值读取（极品，6 次，`ecx` 常量 1..6）：

```
1006C232  B9 01 00 00 00     mov ecx,1
1006C237  FF 15 58 BC 31 10  call [0x1031BC58]     ; GetV(组号, 1)
… 0x1006C252 ecx=2 … 0x1006C2D2 ecx=6，第七次不存在（0x1006C2E3 popal）
```

元素 17 次是完全展开的 `push N / call 0x10065F00`（插件的 GetV 包装器），
`N` 从 `0x1006C570 6A 01` 到 `0x1006C688 6A 11`，**1..17 连续无缺口**。

判定（两段逐字节同构）：

```
1006C2EA  85 C0              test eax,eax          ; eax = 阈值
1006C2EC  7E 14              jle 放行              ; 阈值 <= 0 ⇒ 该位不过滤
1006C2EE  3B 85 50 FF FF FF  cmp eax, 物品值
1006C2F4  7F 0C              jg  放行              ; 阈值 > 物品值 ⇒ 放行
1006C2F6  C7 45 9C 64 …      mov 拦下标志,0x64
```

**拦下的充要条件是 `0 < 阈值 <= 物品值`。**
作者随包说明写的是「值大于 5 的装备不会被回收」，字节是 `>=`；
同一段文字后半句「想任意极品大于等于的不被回收，就全设成 5」才与字节一致。**以字节为准。**

**可叠材料分支完全没有这两道门** —— `极品开关`（`0x1006C19C`/`0x1006C1D1`）与
`元素开关`（`0x1006C527`/`0x1006C55C`）的四处引用全部落在 `0x1006BD39` 之后的
物品种类分支里。这是作者文档「可叠材料是自动忽略极品和元素的」的字节确证。

## 3. 产出计算

**没有任何 RNG。** `sub_1006B020` 的 14 个直接 call 目标里没有 Random，
`[0x1031BCC4]`（概率族的 Random 槽）在本函数一次都没出现。

### 3.1 件数

```
1006BB2A  8B 45 8C     mov eax,[ebp-0x74]      ; item
1006BB2F  66 8B 58 26  mov bx, word [eax+0x26] ; Dura = 堆叠数
```

只有**可叠材料分支**乘这个数（五路各乘一次：`0x1006BC07` / `0x1006BC44` /
`0x1006BC76` / `0x1006BCAE` / `0x1006BCD6`）。
物品种类分支从 `0x1006CD03` 起整段**没有这个乘法，件数恒为 1**。
插件不看 StdMode：谁被写进 `可叠材料`，就按它的 `Dura` 乘。

### 3.2 公式

```
scaled = (倍率 > 0) ? (倍率 * 单价) / 100 : 单价      // 先乘后除
本件金额 = scaled * 件数
```

除 100 是 `imul 0x51EB851F / sar edx,5 / shr+add` 的有符号魔数除法
（`0x1006BBEE`、`0x1006BC2E`、`0x1006BC60`、`0x1006BC8F`、`0x1006BCC5`）。
两步都是 32 位 `imul`，**溢出静默截断**。

### 3.3 落账

| 产出 | 时机 | 引擎函数 | 调用形 |
|---|---|---|---|
| `其他` | **每件立即** | `SetV 0x6DF288` ← `[0x1031BC54]` | `SetV(v1, v2, max(GetV(v1,v2),0) + 本件金额)`，负值钳零在 `0x1006BCFD 7D 02` / `0x1006BCFF 33 C0` |
| 元宝 | **循环结束后一次** | `0x6F8730` ← `[0x1031BC64]` | `eax=Self, ecx=0, edx=总额` |
| 灵符 | 同上 | `0x6DE7BC` ← `[0x1031BC60]`（字段 `+0xBD8`） | `eax=Self, edx=0(reason), ecx=总额` |
| 金币 | 同上 | **`IncGold 0x6D791C`** ← `[0x1031BC5C]` | `eax=Self, ecx=0, edx=总额` |
| 经验 | 同上 | `0x6C87B4` ← `[0x1031BC50]` | `eax=Self, edx=→"经验"(0x10310D08), cl=1, 6 个栈参 (0,0,1,0,总额,1)` |

四路累加器只在**函数入口前**清零（`0x1006B258..0x1006B26A`），循环内不清。

**`0x6D791C` 就是 `IncGold`**：`0x6D7926 mov ebx,[eax+0x15C]`（金币字段）、
`0x6D792E cmp ebx,[eax+0x68C]`（上限）、`0x6D7934 7F 0D jg`（超限则不加、返回 FALSE）。
**插件丢弃这个返回值** —— 见 §4 的原生缺陷。

### 3.4 返回值

```
1006CEBD  83 BD E4 FE FF FF 64  cmp dword [ebp-0x11C],0x64
1006CEC4  75 05                 jne 0x1006CECB
1006CEC6  B8 E7 03 00 00        mov eax,0x3E7      ; 999 —— 死代码
1006CECB  90                    nop                ; ← jne 落点
1006CECC  B8 01 00 00 00        mov eax,1
```

**恒返回 1**；作者想返回 999 的那条被下一条无条件盖掉。
异常臂 `0x1006CEEA B8 19 FC FF FF` 与配置无效臂 `0x1006CF20` 都是 **-999**。
生产脚本正是拿 -999 当「配置文件不存在或语法错误」判据。

## 4. 执行顺序（§5.2 的核心）

原生每件的顺序，**删除在前，结算在后**：

```
① 解析该类型的五路单价                      0x1006B7B6..0x1006BB25
② 五路单价全 <= 0 ⇒ 本件结束，不进删除段     0x1006BB57 jle 0x1006BD2D
③ 重读 FList[idx] 确认还是同一件            0x1006BB7F 3B C6 / 75 45
④ FCount <= 1 ⇒ call [0x10310D0C] (=0x6C1ED8 清空整包)
   FCount >  1 ⇒ TList.Delete(idx)          0x1006BBA6 call [0x1031BC68] (=0x424B30)
                 player.VMT+0x268 (下发删除) 0x1006BBB9
                 Dispose(item)               0x1006BBC2 call [0x1031BC4C]
⑤ 四路累加进总额 + 其他 立即 SetV            0x1006BBD8..0x1006BD2C
⑥ 下一件
─────────── 循环结束 ───────────
⑦ 元宝 → 灵符 → 金币 → 经验，各一次总额落账   0x1006CE42..0x1006CEBD
```

### 失败与回滚

**原生没有任何回滚。** 三处只删不给的窗口，字节确凿：

1. **金币上限**：`IncGold` 在 `m_nGold + 总额 > m_nGoldMax` 时 `0x6D7934 jg` 直接返回 FALSE，
   一分不加。此时全部匹配到的物品**已经在 ④ 删完了**。因为金币是**总额一次性**加，
   顶到上限就是整批全丢。
2. **`其他` 的 SetV 无返回值检查**（`0x1006BD26`），组/下标非法时 `0x6DF2B3/0x6DF2B7`
   两个 `jle` 静默丢弃写入，物品照删。
3. **经验/灵符/元宝同样不看返回。**

### 背包满

不涉及 —— 回收只删不加物品，产出全是货币 / 经验 / V 变量。

### 「FCount <= 1」那条支

`[0x10310D0C] = 0x006C1ED8`（转储里静态已填）。`0x6C1ED8` 从 `player+0x508` 末尾向前
**清空整个背包**（`0x6C1F2C call 0x424B30` + `0x6C1F8D call [edi+0x268]` +
`0x6C1F95 call 0x404690`）。当 `FCount <= 1` 时它与「删掉这一件」等价，
但它**不检查是不是当前这一件** —— 只有在包里确实只剩 ≤1 件时才安全。

## 5. 生产配置验证

`D:\光头卧龙\mud2.0\Mir200\Gs1\MyJson\recycle.json`，11514 B，md5 `af897884085b82d818352303f897f85f`。
按 C# 的读法（cp936 → `System.Text.Json`，重复键后者胜）逐条跑通：

- 根键三个；`回收类型` **11 个**；`物品种类` **313 条**；`可叠材料` **2 条**。
- 313 条全部解析出规则；`可叠材料` 那 2 条指向 `类型2`，`回收类型` 里没有这个名字
  ⇒ **悬空，永不回收**（对应 §2 分支 4）。
- 313 条里 `★` 极品变体 **124**、技能书 **24** —— 与 §5.2 给的数字一致。
- **`  施毒术` 带两个前导空格**，物品库真名是 `施毒术` ⇒ 这本书永远匹配不上。

### 5.2 未命中 = -1 ⇒ 开关默认是**开**的，不是关的

`GetV` 未命中返回 -1 而不是 0（`0x6E427A`），`-1 != 0`（关闭值）⇒ **不拦**。
所以：

- 玩家**从没开过回收面板**时，`V(10,1..10)` 全是 -1 ⇒ 11 个类型**全部可回收**。
- 但 `V(118,68)` 也得是 100 才会调用 `Ys_HuiShou`，而唯一能把它写成 100 的
  `_o2cAll` 只在 `_HuiS` 渲染的对话框里，`_HuiS` 会先把 `V(10,1..9)` 归 0。
  **所以"全开"这一格在生产里够不着** —— 除了下一条。
- **`V(10,10)`（技能书）不在 `_HuiS` 的归零名单里**，所以打开过面板、开了自动回收之后，
  技能书那一档仍然是 -1 ⇒ **24 本技能书会被以每本 100 金币回收**。这是生产的真实行为，
  不是缺陷推测。
