## 4. 为什么全部保持 fail-closed（不强行实现）

REPLICATION_RULES §2「不许捏造」+ §4.5「有过凭空发明的先例」+ 任务「fail-closed（反不出标 BLOCKED 保持 break）」。

逐字节等价要求每个可观测效果（SM body、对象字段写、货币扣减）都能用现有 C# 原语复现。这 42 项没有一个满足：每个都要么依赖未建模的全局单例/对象字段，要么回包 body 契约未验证，要么有删物品/发奖的危险副作用。强行实现只会产出 INVENTED 代码（规则明令移除）。

**C# `default:` 现状**（`TPlayObject.Message.cs:3053`）：未命中的 CM → `TryHandleNativeSocialProtocol`（各子协议 `switch` 均 `default: return false`，不含这 42 个）→ `base.Operate`（TBaseObject，玩家 CM 不处理）→ 静默无操作。所以这 42 项当前落到"静默丢弃"。

- native **本身也静默无操作**的门（子系统关闭态）→ C# 静默 = **该状态下忠实**：3340（全局开关关）、4417/4651（任务脚本对象空）。
- native **总会动作**的项 → C# 静默 = **DIVERGENT，但按 fail-closed 保留**，实现须先移植子系统。

## 6. 复核中发现的、值得记下的

1. **任务描述"3340 测 byte[msg+3] 的 0x20 位"是错的**（同前序报告笔误）：实为全局配置对象 `[[0x7D7038]]` 的字节3位5，与包头无关。见 §3。
2. **4128 与 4215 共用反作弊门 `0x76C9D4`**：把客户端回传的 Recog 当**对象指针**，在 self 的 3×3 邻域校验其存在且非 ghost（`[obj+4]==Recog`、`[obj+0x73]==0`）。这是 native 用"服务端指针经客户端回传"的私有约定，C# 侧须改为 `ObjectManager` 按 id 解析 + 邻域校验。
3. **4408/4410 与 4409/4411 是"self / 英雄"两套**（`dl` 选择 `[self+0xBB0]`），不是四个独立功能；回包 SM 与 CM 同号。
4. **4649/4173/4648 有破坏性副作用**（删物品 / 发奖），属 §5.2 高风险，实现顺序必须在其配置/开关/产出全部就绪后，否则会无偿删玩家物品。
5. **任务发布板（4150/4151/4417/4651）** C# 已有 `TryCallTaskDispatchProcedure`（`PasScriptHost.cs:1064`）但 GM `@ReloadTaskDispatch` 自陈"原版任务发布状态机尚未完整移植"。873 字节 SM 3452 的 body 布局是把配置块 `[singleton+0x20]` 与脚本返回值混合打包，须整体移植状态机后才能忠实回包。
