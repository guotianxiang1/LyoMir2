### 4.2 报而不改（大缺口/设计项）
1. **行会四表 schema 自建**：原生加载器另以 `Create table if not Exists` 自建 Gild/GildMember/GildRelation/GildConcern；
   C# 侧 Corps 与 Gild store **均不建表**，且 `NativeCorpsStore.LoadGildConcerns` 对缺表有 best-effort 降级 —— 表明
   schema 由原生/共享迁移拥有的**一致、有意**部署设计。属部署/引导层，非本分片契约缺口；改动会触及活加载路径，故报而不改。
2. **BigBag 背包容量扩展**：TCFP-15 的 `BagCapacity.Of` 在启用 `无限背包` 插件时可 >48（原生硬编码 `0x30`）。
   这是全仓一致、专门文档化（`staging/m_bagcap_impl_20260813.md`）的**刻意扩展**，插件关闭时逐字等于原生。非背离缺陷。
3. **DecGold 站点冗余 GoldChanged**：`TPlayObject.Base.cs:1676` 等处在 `IncGold`/`DecGold`（内部已发通知）后再手发 GoldChanged，
   属已知冗余（源码注释明示留待单独清扫），且不在 TCFP 交易提交路径内，超出本分片范围。
